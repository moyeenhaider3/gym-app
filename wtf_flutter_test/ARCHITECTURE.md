## Monorepo Structure

```

├── shared/              # Dart package — models, services, widgets, utils
├── guru_app/            # Flutter app — Member persona
├── trainer_app/         # Flutter app — Trainer persona
└── token_server/        # Node.js Express — relay hub + 100ms tokens
```

## Data Flow

1. **Chat:** App → POST message to server → server stores → other app polls → receives
2. **Video Call:** App → GET token from server → join 100ms room (cloud handles media)
3. **Scheduling:** Member → POST request → Trainer polls → approves/declines → Member polls update
4. **Session Logs:** Written to server on call end → both apps can read

## State Management

**Bloc** pattern throughout. Key blocs:
- `ChatListBloc` / `ConversationBloc` — chat feature
- `SchedulerBloc` — call request workflow
- `PreviewCubit` / `RoomOverviewBloc` — 100ms video call
- `SessionLogBloc` — session history

## Storage

- **Hive** — local cache per app (fast reads, offline capability)
- **Token server in-memory** — source of truth for shared data
- Each app syncs from server on poll, caches in Hive

## 100ms Integration

- Package: `hmssdk_flutter`
- Pre-created room: `69eb0eb2d63b6068ded6f1f3`
- Roles: `host` (trainer), `guest` (member)
- Auth: JWT HS256 generated by token server
- Manual UI (not `hms_room_kit`) for full control

## Network

- Token server binds to `0.0.0.0:3000`
- Apps use Mac's local IP (e.g., `192.168.0.122:3000`)
- All devices must be on same WiFi network
